JEV 值得接进企业 Agent 吗？我们拿真实业务试了试

2026年9月24日
|

面对JEV带来的低成本决策想象，我们用真实日报业务做了一次测试。它的优势有多大，能替代什么，又有哪些错误不会随着低价一起消失？

一个AI模型，如果不再负责写文章、生成代码，而是专心帮软件做选择，会发生什么？

这是JEV让我感兴趣的地方。TypeSafe对它的定位很明确：把输入变成软件可以直接使用的结构化决策。对于正在做企业Agent的人，这个方向很有吸引力。很多时候，我们调用一次大模型，最后需要的只是一个项目编号、一个分类，或者“这件事应该交给谁”。

但看过介绍之后，我更想知道另一件事：离开演示，放进每天真的有人在用的业务流程，JEV还能带来多少价值？

于是，我们拿交付团队收集日报的场景做了测试。没有另外编一套展示题，而是从实际消息和项目目录里取输入，让JEV、Qwen和DeepSeek做同一项判断。

先说我的感受：这次测试给了我认真考虑JEV的理由。在一个明确的业务节点上，它用很低的调用成本，取得了接近部分通用模型策略的判断效果。不过，要把这个优势变成可以放心运行的企业服务，还需要解决一些不那么醒目的问题。

先把它放进一件真实的小事

我们团队有一个钉钉交付小助理，每天向同事收集工作日报。同事告诉它做了什么、花了多久、参与了哪些项目，它负责更新AI表格，缺什么再问什么。

如果你做过类似系统，就知道消息通常不会像表单一样整齐。有人先发工作内容，过一会儿补“8小时”；有人只写客户简称；有人临时帮另一个项目做了事，人员清单还没有绑定。助理需要记录实际发生的工作，不能因为名单没更新就拒绝提交。

这件事已经在运行，只是Agent处理起来有时比较慢。我们在上一篇《让 Agent 少走重复的路》里做了第一步优化：把历史任务中的消息、工具调用、返回和保存结果串起来，观察哪些步骤一再出现。

补充工时之前，先找当天记录；更正数值时，替换而不是累加；写入之后，回读确认。这些执行关系反复出现，追问和失败恢复也有规律。开发者与Coding Agent对照真实轨迹，把它们整理成Fast Workflow，外围Agent继续负责沟通和例外。

因此，这次尝试有一个很具体的起点：工作流已经有了，我们想知道里面的某个判断，能不能换成更便宜的实现。

这张图是基于实际经验重新设计的新版候选流程，不代表我们已经把JEV部署到了线上。它把模型的工作分成两段。

第一段L1读懂这次消息：说的是哪天，哪些是正文，“再加1小时”是增加还是更正，提到了哪些项目。第二段L2才拿着项目原话，对照正式目录，判断对应哪个项目。

我们选中的是L2。它的选项天然存在于业务表里。 程序查出完整项目目录，再加一个“无法唯一确定”，模型就有了可以回答的选择题，不需要另一个模型提前替它出题。

L1没有这么直接。用户会怎样描述工作，事先列不完；正文、日期和数值仍需要开放提取。把它整体换成本次使用的JEV Choice接口并不可行。至于查询、计算、写入和回读，程序本来就在做，也不需要为了用新模型而改造。

成本差距确实很大，但要看它和谁比

我们让新版L1处理14条历史真实日报，9条通过校验，得到20个项目表述。另5条在上游就遇到了原文依据或工时校验问题，单独保留，没有手工修好后加入L2测评。候选则来自实际业务表查询得到的61项项目目录，不按人员绑定筛选。

五种策略使用相同的消息、L1输出和目录，每例运行两轮。总共200次调用，都正常返回了合法结果，没有超时。下面比较的是项目匹配这一步，不是整个日报流程。

先看这张图。横轴是处理每千条同类日报所需的L2调用费用，纵轴是一条日报中的项目判断是否全部正确。越靠左上，越符合我们“少花钱、把事做对”的期待。

JEV最值得注意的位置，是它和Qwen关推理处在同一高度，却明显更靠左。 两者整条日报全对都是13/18，JEV调用成本低约95%。与DeepSeek开推理相比，两者项目判断同为35/40，JEV成本低约91%至95%，但整条日报全对少了一次。

完整结果如下。这里的“整条日报全对”，仅要求这条日报中的所有项目判断正确，不包含正文、工时、保存等其他环节。

这已经是有意义的性价比信号，值得进入工程选型。但如果只挑最贵的Qwen开推理作参照，说“成本降低98%”，很容易让读者误以为它在所有方面都胜出了。Qwen开推理这一轮确实更准：40次项目判断对了38次，JEV是35次。

更现实的经济基线是DeepSeek Flash关推理。与它相比，JEV每千条同类日报的L2费用少约1.46至4.77元，40次项目判断多对4次。不过，JEV中位耗时2.26秒，慢于DeepSeek关推理的1.38秒，也慢于Qwen关推理的1.34秒。

所以，这次吸引我的并不是“JEV全面领先”，而是：在一项真实业务判断上，我们多了一个成本明显更低、判断效果仍有竞争力的选项。

这组数据也有清楚的范围。只有9条日报，重复两轮并不等于18条独立案例；本轮为统一适配，按项目逐个调用，再累计到整条日报，因此费用和时间不能直接套到原生批量L2或线上系统。图中的DeepSeek横线是忙闲价格区间，不是准确率置信区间。

它选错的时候，看起来也很正常

把错题拿出来看，比比较排行榜更有意思。

20个项目表述里，8个可以唯一匹配。这8个项目，两轮测试中五种策略全部正确。真正拉开差距的是另外12个：目录里没有明确对应，或者原话不足以区分几个候选，本应交给外层确认。

举一个真实案例的结构，客户名作了替换。同事只说“某保险公司的项目”，目录里却有这家公司的K8S、PM、TM三个独立项目。业务已经确认它们不是同一个项目。只知道客户名，还不足以决定这次工时应该归到哪一个。

JEV有一轮直接选了PM。

它没有编造项目，没有返回坏掉的JSON，也没有调用失败。选出的编号就在目录里，程序检查能够通过。但这次选择缺少依据，仍然是错误归属。

JEV的5次错误都属于这种“该确认却选了”的问题，涉及客户简称、产品平台名和未明确客户的产品版本。其他模型也会犯同类错误。这24次应待确认的判断中，Qwen开推理正确退出22次，JEV和DeepSeek开推理各19次，Qwen关推理18次，DeepSeek关推理15次。

限制输出范围，能让软件更容易接住答案，却不能保证答案在业务上成立。 这是我觉得企业使用者尤其需要留意的一点。

“答错就交给大模型”听起来很好，问题在于，系统未必知道这次答错了。一个合法但错误的项目编号，不会自己触发异常。JEV提供的置信度是否能帮助识别这些情况，也需要另外校准；本轮没有测试这个能力，不能把它当作已经成立的兜底。

这也解释了为什么我们需要保留外层Agent和必要的确认路径。一个便宜的决策节点，可以缩短常见路径，却不能独自承担整件事情的可靠性。

用好JEV，要先把“选择题”和“填空题”拆开

回到最初的问题：围绕JEV的期待，究竟有没有真实商业意义？

从这次测试看，有，而且已经能找到具体的位置：像L2这样的项目匹配节点。 候选来自真实业务目录，任务边界清楚，JEV以明显更低的调用成本，取得了接近部分通用模型策略的判断效果。这给出的已经是一种可落地的分工方向。

理解这个方向，可以把工作流里的模型任务分成“填空题”和“选择题”。

L1更像填空题。同事今天做了什么，用了多久，提到了哪个项目，这些内容无法提前穷举成选项。我们需要通用大语言模型读懂消息，提取原文、数值和修改意图。这部分能力仍然要保留。

L2更像选择题。项目原话已经提取出来，正式项目目录也已经查到，接下来是在有限候选中找到对应项，或者判断需要确认。这样的节点，就可以引入JEV。

工作流里的任务适合的分工
从自由表达中提取正文、日期、投入和项目原话通用大模型做“填空题”
将项目原话对应到已有目录JEV做“选择题”，保留待确认分支
查询记录、计算工时、校验字段、写入与回读程序执行确定性步骤
信息不足、特殊任务和异常沟通外层Agent接管

这样设计的价值，是让每种能力只承担它需要承担的工作。通用大模型不必为后续每一次有限选择继续付出同样的调用成本，JEV也不需要被迫处理原本不适合它的开放提取。查询、计算和保存则留在程序里。

这里有一个容易走偏的地方：为了用JEV，先让另一个模型把整段日报消化一遍，再为日期、正文和工时生成一套答案选项。这样虽然也能得到选择题，却可能重复付出了理解成本。我们这次选择L2，恰好因为它的候选本来就在项目表里，而L1提取项目原话本身也是日报流程需要完成的工作。

先识别业务中自然存在的选择，再把它从开放理解中拆出来，才能充分利用JEV的低成本特点。

企业Agent的降本，开始变成一个流程设计问题

这轮实践让我对JEV的判断更明确了：它在特定环节已经展示了实用价值。对企业工作流而言，我们可以保留大模型处理开放问题的能力，同时让JEV承担合适的有限决策，让同一条流程采用不同的模型实现。

当然，“可以承担L2”不等于“每次选出的项目都可以直接写入”。前面的错误说明，候选合法性校验还不够，模糊归属需要复核或确认。要把效果控制住，就应当对每个节点分别测评，确定自动处理范围，并为不能可靠处理的情况保留接管路径。本轮证明了L2的低成本判断能力，尚未证明这些错误都能被自动识别。

在这个前提下，降低综合成本的路径已经很清楚：让大模型完成必要的填空，让JEV完成适合的选择，让程序完成确定的执行。 高频任务反复经过这些节点，单次调用的成本差异才有机会累积为整个系统的收益。收益的具体幅度仍要连同复核和接管一起实测，不能把L2的降幅直接当作整个Agent的降幅。

这也延续了我们从Fast Workflow开始的思路。先从真实任务轨迹中整理可复用的推理与执行链，再进一步拆清每个节点需要什么能力。流程越清楚，模型替换越有依据，成本和效果也越容易分别衡量。

所以，JEV带给企业Agent的启发，不只是又多了一个便宜模型。它让我们更有理由重新检查工作流：哪些地方需要大模型开放地理解，哪些地方其实只需要做一道选择题？

我的结论是：JEV的商业价值已经在这类有限决策节点上显现。把“选择题”和“填空题”拆开，在效果可控的基础上充分使用低成本决策，是值得采用的工作流设计方向。这次的L1与L2，就是一个具体的起点。
